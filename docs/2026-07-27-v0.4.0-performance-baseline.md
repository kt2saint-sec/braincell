# v0.4.0 performance baseline

This document records reproducible baseline observations for the project-only
release. These are not performance promises.

Measured branch state: `279315faf6cf144419aef9abf1a27ecc95308a41`

Command:

```bash
.venv/bin/python scripts/pool_bench.py --iterations 30 --notes 40 --chunks 40 --port 8977
```

Environment:

- OS: Ubuntu Linux, kernel `6.17.0-1030-oem`, x86_64
- Python: 3.11.14
- CPU: AMD Ryzen 9 9950X, 16 cores / 32 threads
- RAM at run time: 123 GiB total, 49 GiB available
- Data location: disposable `XDG_DATA_HOME` under `/tmp`
- Seed data: 16 disposable Projects, 40 memory notes and 40 document chunks per
  Project, deterministic local vectors, no Ollama or hosted embedding request
- GUI measurement: `QT_QPA_PLATFORM=offscreen`,
  `QTWEBENGINE_CHROMIUM_FLAGS=--no-sandbox`

## Hook overhead

N/A for release runtime measurement. The retired hook module remains only as a
fail-quiet compatibility entry point at `braincell/family_hook.py`; normal setup
uses Project-local Automatic Pool recall and does not install that hook for
runtime memory work. The source evidence checked by the benchmark was
`braincell/family_hook.py` and `braincell/install.py`.

## Limitations

- This benchmark uses deterministic local vectors to isolate BrainCell Store and
  Pool query overhead from embedder availability and model-load variance.
- The query measurements exercise the Store and explicit named Pool read paths
  directly. Console startup timings are measured through shipped console scripts.
- The native GUI number is an offscreen readiness probe of the local status
  endpoint, then the process is terminated. It is a startup baseline, not a
  desktop interaction benchmark.
